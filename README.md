# ESP32 FTMS Indoor Bike Sensor

## Introduction

This project converts a conventional magnetic resistance exercise bike into a smart FTMS-compatible indoor bike using an ESP32.

The system measures real-time pedaling cadence through a magnetic reed switch sensor, applies an adaptive EMA filtering algorithm to stabilize RPM readings, estimates rider power output using a quadratic mathematical model, and transmits cadence, speed, and power data over Bluetooth Low Energy (BLE) using the official FTMS standard.

The firmware was specifically designed to improve compatibility with indoor cycling applications such as MyWhoosh, Zwift, Kinomap, and other FTMS-compatible platforms while maintaining smooth and realistic sensor behavior.

---

# Main Features

- Real-time cadence acquisition using a magnetic sensor
- Adaptive EMA filtering with dynamic α adjustment based on RPM delta
- Quadratic power estimation model
- BLE FTMS Indoor Bike compatibility
- Simulated speed generation for app compatibility
- Resistance level detection using a potentiometer
- Automatic braking and stop detection
- BLE data transmission every 300 ms

---

# Instantaneous Cadence Acquisition

A magnetic reed switch sensor is mounted on the bicycle frame. The sensor detects the passage of a magnet attached to the crank pulley.

Each time the crank completes one full revolution, the magnet activates the sensor and generates a discrete electrical pulse.

This creates a sequence of time events:

```text
t₀, t₁, t₂, ..., tₙ
```

To calculate instantaneous pedaling cadence, the firmware measures the elapsed time between the current pulse (`tₙ`) and the previous pulse (`tₙ₋₁`):

```text
Δt = tₙ - tₙ₋₁
```

Since time is measured in microseconds for maximum precision, cadence in revolutions per minute (RPM) is calculated as:

```text
Cadence (RPM) = 60,000,000 / Δt
```

---

# Cadence Filtering

Directly transmitting raw RPM values produces abrupt fluctuations and unstable visual behavior inside cycling applications.

To smooth the signal, the firmware implements an EMA (*Exponential Moving Average*) filter.

---

# EMA Filter

Unlike a simple average, the EMA filter gives greater weight to recent samples while progressively reducing the influence of older values.

```text
RPMfiltered(n) = α · RPMinstant(n) + (1 - α) · RPMfiltered(n - 1)
```

Where:

- `α` is the smoothing factor (`0 < α < 1`)
- High α → fast response but more noise
- Low α → smoother signal but slower response

---

# Adaptive Improvement (Delta-Based α)

To avoid choosing between smoothness and responsiveness, the firmware dynamically adjusts the value of `α` according to RPM variation intensity.

First, the algorithm calculates the absolute RPM difference between the current and previous pedal stroke:

```text
δₙ = | RPMinstant(n) - RPMinstant(n - 1) |
```

Then, α is automatically adjusted:

| RPM Delta | Behavior |
|---|---|
| `δₙ < 3` | Maximum smoothing → `α = 0.12` |
| `3 ≤ δₙ < 10` | Progressive transition |
| `10 ≤ δₙ < 20` | Fast response |
| `δₙ ≥ 20` | Instant response → `α = 0.95` |

Interpolation formulas:

```text
α = 0.12 + ((δₙ - 3) / 7) · 0.23
```

```text
α = 0.35 + ((δₙ - 10) / 10) · 0.45
```

---

# Internal Alpha Smoothing

To prevent abrupt jumps in the smoothing factor itself, α is also stabilized using a second internal EMA filter:

```text
αsmooth(n) = 0.70 · α(δₙ) + 0.30 · αsmooth(n - 1)
```

This significantly improves visual stability while preserving fast responsiveness during accelerations and sprint efforts.

# Power Estimation

The exercise bike does not include physical torque sensors or strain gauges.

Therefore, rider power output is mathematically estimated using:

- Filtered cadence (RPM)
- User-selected magnetic resistance level

---

# Magnetic Resistance Principle

The braking system operates using Eddy Currents.

As the metallic flywheel rotates, it cuts through the magnetic field generated by permanent magnets. This induces microscopic electrical currents inside the flywheel, creating an opposing magnetic field that generates resistance without physical contact.

The user manually changes braking intensity by modifying the distance between magnets and flywheel.

---

# Mathematical Power Model

Magnetic braking force increases approximately linearly with flywheel speed.

However, since power equals force multiplied by velocity, rider effort grows quadratically.

The firmware implements the following model:

```cpp
Power (W) = (K · RPM²) + (C · RPM)
```

Where:

- `K` → quadratic coefficient associated with magnetic braking
- `C` → linear coefficient associated with mechanical friction losses

---

# Resistance Level Detection

The bike includes a physical potentiometer connected to the resistance selector.

The ESP32 reads this value through its 12-bit ADC:

```text
ADC Range: 0 → 4095
```

To reduce electrical noise, the firmware averages 8 consecutive samples before converting them into 8 discrete resistance levels.

```cpp
Level = constrain( ((ADC - 120) / (3980 - 120) * 8) + 1, 1, 8 )
```

---

# Dynamic Coefficient Table

Each resistance level uses specific `K` and `C` coefficients:

| Level | K | C |
|---|---|---|
| 1 | 0.006 | 0.05 |
| 2 | 0.009 | 0.07 |
| 3 | 0.012 | 0.10 |
| 4 | 0.017 | 0.14 |
| 5 | 0.022 | 0.18 |
| 6 | 0.030 | 0.24 |
| 7 | 0.039 | 0.30 |
| 8 | 0.050 | 0.38 |

---

# Calculation Example

Example:

- Resistance level: 4
- Cadence: 80 RPM
- `K = 0.017`
- `C = 0.14`

Quadratic component:

```text
0.017 × 80² = 108.8 W
```

Linear component:

```text
0.14 × 80 = 11.2 W
```

Estimated total power:

```text
120 W
```

# BLE FTMS Implementation

The ESP32 implements the official FTMS profile defined by Bluetooth SIG.

Every 300 ms, an Indoor Bike Data packet is automatically transmitted using BLE notifications.

---

# FTMS Packet Structure

The packet contains three main fields declared through the `0x0044` flag mask:

| Bytes | Field |
|---|---|
| 0–1 | Flags |
| 2–3 | Simulated speed |
| 4–5 | Cadence |
| 6–7 | Power |

All values are transmitted using *little-endian* format.

---

# Cadence Encoding

The FTMS standard uses a 0.5 RPM resolution.

Therefore, cadence is transmitted as:

```cpp
cadenceValue = cadence × 2
```

The application internally divides the received value by two.

---

# Simulated Speed

Some cycling applications reject FTMS packets if the speed field is absent.

Since the bike does not include a physical speed sensor, speed is artificially derived from cadence:

```cpp
speedValue = cadence × 30
```

This improves compatibility with third-party applications.

---

# BLE Notify vs Read

The ESP32 uses the BLE `notify` mechanism.

Once the application subscribes to the `Indoor Bike Data` characteristic, the ESP32 automatically transmits new packets every 300 ms without requiring manual requests.

If no device is connected, transmission is automatically skipped.
